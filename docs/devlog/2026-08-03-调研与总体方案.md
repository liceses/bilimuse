# 调研与总体方案 开发日志

- 日期：2026-08-03
- 里程碑：M0（项目立项 / 调研）
- 关联：[idea.md](../../idea.md)、[PLAN.md](../../PLAN.md)

## 目标与验收

- 目标：确认"B 站深度定制音乐下载器"的可行技术链路，选定技术栈，拆出里程碑。
- 验收标准：
  - 每个目标功能在现有开源项目中都没有被完整解决，且我们的差异化点（按歌词反查、时间轴校准）有成熟库可用；
  - 明确的风险点都有对策，不依赖单一逆向接口。

## 方案与思路

**结论：从零构建 Python 项目，不 fork。** 备选：go-music-dl（AGPL-3.0 传染 + 无歌词/无校准）、wasm-music（无 LICENSE + 架构陈旧）。否决理由：授权风险 + 核心差异化能力缺失。

七个目标需求（歌名搜索/选版本/下载/打标签/找歌词/找封面）中六个已有成熟覆盖，**真正无人做好的只有两点**，即本项目核心价值：

1. **按歌词全文反查歌曲**：B 站官方搜索只索引标题/简介/标签（`hit_columns` 仅此三值），不索引字幕/弹幕。可行链路为**两跳反查**：歌词片段 → Musixmatch(`q_lyrics`) / LRCLIB / 网易云 → 得歌名+歌手 → B 站 `wbi/search/type` 按标题搜版本。
2. **歌词时间轴自动校准**：`lyric-align`（faster-whisper 词级时间戳 + 字符模糊匹配锚定，CJK 优先）做强制对齐，`audio-offset-finder`（MFCC 互相关求整体偏移 ~0.01s）做偏移校正。

## 技巧

### 两跳反查（歌词 → 歌名 → B 站版本）

- 核心思路：B 站不可直接按歌词搜，用外部歌词库先把歌词反查成曲目，再回 B 站选视频版本。这是现有项目都没想到的关键路径。
- 关联：[PLAN.md](../../PLAN.md) 数据流 [1]。

### 技术栈选型

- `httpx`（异步 HTTP + 自定义 Wbi 签名）、`pydantic` v2（数据模型）、`mutagen`（ID3/FLAC/MP4 打标签 + 内嵌封面歌词）、`faster-whisper` + `lyric-align`（校准）、`audio-offset-finder`（偏移校正）、`ffmpeg`（mp3/flac 转码，外部命令）、CLI 用 `typer`+`textual`，Web 二期用 `fastapi`。
- 核心库全部挂在核心逻辑上：`lyric-align`/`audio-offset-finder` 需做可行性实测（见 M4）。

## API / 库 速查

### B 站 wbi/search/type（搜索视频）

- 用途：按关键词搜索 B 站视频，取候选版本（bvid + cid）。
- 关键点：需 Wbi 签名；返回 `hit_columns` 仅标题/简介/标签；过滤条件——hit_columns 含 title、音乐分区、时长相近。
- 调用处：计划在 `bilimuse/providers/bilibili.py`（M1 实现）。

### B 站 x/player/wbi/playurl（DASH 音频流）

- 用途：取纯音频流。`fnval=4048`，未登录基础音质，登录 320k / VIP FLAC(30251) / 杜比(30250)。
- 调用处：计划在 `bilimuse/providers/bilibili.py`（M2 实现）。

### 网易云 cloudsearch + song/lyric（元数据反查 + 歌词）

- 用途：反查真实歌名/歌手/专辑/封面/时长；`song/lyric` 取歌词。
- 关键点：weapi 需逆向签名（AES+RSA），接口易变 → 接口层抽象、多源降级。

### LRCLIB /api/get（歌词主源）

- 用途：按 track+artist+album+duration 签名匹配返回标准 LRC。免费无 key，约 300 万条。
- 关键点：作主源避免主链路依赖逆向接口。

### B 站 x/player/wbi/v2（AI 字幕兜底）

- 用途：获取 AI 字幕歌词，用 `music` 置信度字段筛演唱段。质量差，仅兜底。

## 踩坑

- **B 站风控 -412** → 需 Wbi 签名 + buvid3 cookie + 合理 UA/Referer，先 GET 首页拿 cookie → 失败重试 + 退避。对策见 PLAN 风险表。
- **whisper 对歌唱识别不准** → 调参（关 VAD、CJK 阈值、必要时分离人声）；仅当快速校准无法收敛时启用（M4 实测）。

## 验证

- 命令：调研结论经与现有开源项目（go-music-dl 3.7k★ / wasm-music / TuneScout-v2 / MusicFlow）逐一对比，见 [idea.md](../../idea.md) 对比表。
- 结果：差异化点（歌词全文反查、时间轴校准）现有项目均为"无"，可行性由 `lyric-align`/`audio-offset-finder` 等成熟库支撑。后续 M1~M6 逐里程碑验证。
