## 目标与验收

- 目标：DASH 音频流下载、按格式输出（m4a 直拷 / mp3、flac ffmpeg 转码）、文件名模板命名、SQLite 去重入库
- 验收标准：
  - `bilimuse download <BV号>` 能下载单曲音频到配置目录，文件名符合模板 ✅
  - m4a 直拷可用（无需 ffmpeg）✅；mp3/flac 在 ffmpeg 存在时可转换，缺失时给出明确报错 ✅
  - 重复下载同一 bvid+cid 会去重跳过 ✅
  - 下载记录写入 SQLite ✅

## 方案与思路（含否决方案）

- 下载流：`pick_audio` 拿最高码率流 → httpx stream 下载 → `.part` 临时文件原子改名，避免半截文件。
- 格式策略：
  - `m4a`：B 站 DASH 音频本身就是 fMP4(AAC)，m4s 直拷改名 `.m4a`（不重编码）。
  - `mp3`：ffmpeg `-c:a libmp3lame -q:a 2`。
  - `flac`：**仅当 playurl 返回 VIP flac 流(30251)时**才真无损；用 ffmpeg `-c:a copy` 重封装。无 flac 源时降级 m4a 并提示。**否决** AAC→FLAC 转换（有损转无损无意义）。
- 转码用 `asyncio.create_subprocess_exec` 调 ffmpeg CLI（与 go-music-dl 同思路），不引入 pyav 重依赖。
- 去重：SQLite `UNIQUE(bvid, cid)`，下载前查询；`INSERT OR REPLACE` 幂等。

## 技巧

- 进度显示：`Content-Length` 做总量，`aiter_bytes()` 累加；每 1% 打一次 `\r` 覆盖行 → `bilimuse/services/download.py:53`
- **下载前先查 ffmpeg**：`_decide` 判定需转码后、`download_stream` 之前检查，缺 ffmpeg 直接报错，避免下载到一半才失败 → `download.py:87`
- ffmpeg 用 `-loglevel error` 屏蔽噪音，stderr 只在失败时读出 → `download.py:70`

## API / 库 速查

- `httpx.AsyncClient.stream`：流式 GET；`r.headers["Content-Length"]` 总量，`r.aiter_bytes()` 分块写盘 → `download.py:40`

## 踩坑

1. **typer 0.27 重写，`Exit` 不再支持 `message`**
   现象：`raise typer.Exit(message="...")` 报 `TypeError: Exit.__init__() got an unexpected keyword argument 'message'`。
   原因：typer 0.27 起不依赖 click（`pyproject` requires 仅 rich/shellingham），`Exit.__init__(self, code: int = 0)`。
   解决：先 `typer.echo(msg, err=True)` 再 `raise typer.Exit(code=1)` → `cli.py:78`。
2. **文件名纯非法字符**
   现象：`sanitize_filename("///")` 返回 `___` 而非空。
   设计：`_ILLEGAL.sub("_", name).strip(". ")`，结果 `___` 是合法 Windows 文件名，属预期；仅完全空串回退 `untitled` → `download.py:23`。
3. **测试断言期望错误**
   现象：`test_sanitize_filename` 断言 `"///" → "untitled"` 失败。
   解决：修正断言为 `"___"`（符合实现语义）→ `tests/test_download.py:10`。

## ffmpeg 可选内嵌（补充，同日）

### 方案与思路

需求：内嵌 ffmpeg，不要求用户系统环境；方便他人拉取后部署到个人电脑。

- 方案 A：`imageio-ffmpeg`（选定）—— pip wheel **直接打包**静态 ffmpeg（~60MB，win/linux/macos × arm64/x86_64，ffmpeg 7.1，含 libmp3lame），从 PyPI 拉取（国内可用清华镜像，**不经 GitHub**），装完即离线可用。
- 方案 B：`static-ffmpeg` / `portable-ffmpeg`—— wheel 小，但**首次调用从 GitHub 现下载**，国内反而慢，且依赖第三方托管可用性。否决。
- 定位：ffmpeg 做成**可选 extra**，核心依赖保持轻量；纯 m4a 用户零 ffmpeg 依赖。
- 部署工具：`setup.ps1` / `setup.sh` 一键建 venv+装依赖（`--with-ffmpeg` 开关）；`bilimuse doctor` 检测环境。

### 技巧

- `find_ffmpeg()` 三级回退：`config.ffmpeg_path` → 系统 PATH(`shutil.which`) → `imageio_ffmpeg.get_ffmpeg_exe()`（**懒 import**，未装 extra 不报错）→ `bilimuse/services/download.py:32`
- `imageio_ffmpeg.get_ffmpeg_exe()` 自带三级（`IMAGEIO_FFMPEG_EXE` 环境变量 → 内置 → 系统），所以代码里只需兜一层 config + 直接调它。
- mp3 转码用 `-c:a libmp3lame -q:a 2`（VBR，码率随源质量自适应）。

### API / 库 速查

- `imageio_ffmpeg.get_ffmpeg_exe()`：返回内置/系统 ffmpeg 路径；未找到时 `raise RuntimeError` → `download.py:32`
- `pip install -e ".[ffmpeg]"`：可选 extra 语法，装 imageio-ffmpeg → `pyproject.toml`

### 踩坑

- **装完 extra 后 mock 测试失效**：`test_find_ffmpeg_none` 用 `delitem(sys.modules, ...)` 模拟"未安装"，但 `import imageio_ffmpeg` 会重新加载已装的包。改为 `setitem(sys.modules, "imageio_ffmpeg", None)`（Python 对 None 视为 import 中止 → 抛 ImportError）→ `tests/test_download.py:44`
- **GPL 再分发**：ffmpeg 是 GPL 组件，未来若 PyInstaller 打包分发需附带源码/许可声明；个人自用无影响。

### 验证

- `bilimuse doctor`（未装 extra）：`ffmpeg: 未找到。m4a 不受影响；mp3/flac 需执行 pip install -e '.[ffmpeg]'...` ✅
- `pip install -e ".[ffmpeg]"`（清华镜像）→ `get_ffmpeg_exe()` 返回 `venv\Lib\site-packages\imageio_ffmpeg\binaries\ffmpeg-win-x86_64-v7.1.exe` ✅
- `bilimuse doctor`（装后）：`ffmpeg: 找到（imageio-ffmpeg 内置: ...）` ✅
- 端到端 mp3：`bilimuse download BV1T7xazHExs --format mp3` → 2.4MB，magic `49 44 33`(ID3)，`Duration 00:02:32.92, mp3 44100Hz stereo 128kb/s` ✅
