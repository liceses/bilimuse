- 日期：2026-08-05
- 里程碑：M10（验收测试集）
- 关联：[统一入口](2026-08-04-deploy-test.md)、[lyric-align](2026-08-03-lyric-align.md)

## 目标与验收

- 目标：一套可落地、可重复跑的验收测试集——覆盖全部功能/语种/边界/格式/校准，带「标准答案」（机器校验）+「人工评审」（主观项）。
- 验收标准：
  - `tests/e2e/run_testset.py` 真实网络跑 34 条用例全 PASS（含 whisper 校准）。
  - Web 端 e2e（pytest `-m e2e`）3 条通过；默认 `pytest -q` 不跑 e2e（70 单元不受影响）。
  - `tests/e2e/align_bench.py` 用 `gold/` 人工标注时间戳量化 whisper 对齐误差。
  - 用例 bvid/期望值已实地固化，重跑不重复下载、不被去重误伤。

## 方案与思路（含否决方案）

- 方案 A：YAML 用例 + 独立运行器（`run_testset.py`）。→ **采纳**。运行器能输出人工评审表、断点续跑（--only）、缓存复用、probe 固化模式；纯 pytest 参数化无法承载这些。
- 方案 B：录制 VCR fixture 离线回归。→ 否决（当前阶段）。真实网络是落地验证重点，VCR 留作后续。
- 方案 C：固定搜索 index 选版本。→ 否决。B站 排序受风控/登录态漂移，改用「固定 bvid + 搜索成员集/lyric_hit」断言。
- 标准答案双轨：`expect`（机器校验：标签/时长/语言/歌词/校准方法）+ `review`（人工：对齐质量 A/B/C），报告表驱动。
- gold 校准基准：5 首人工标注时间戳（`gold/G0*.json`），whisper 对齐后逐行对比，中位误差 ≤1.5s 优 / ≤3s 过 / >3s 败。

## 技巧

- **缓存复用**：`key = {bvid}:{fmt}:align{0|1}` → `report/download_cache.json`；命中且文件存在则跳过下载。对齐开/关是不同 key，避免错误复用 → `run_testset.py:_cache_key`
- **每用例独立下载目录** `dl/<case_id>/`：不同视频可能产出**同名**文件（如两个晴天视频都叫「周杰伦 - 晴天.m4a」），共享目录会被后跑用例覆盖 → 时长校验炸。分目录根治 → `run_testset.py:run_case`
- **每轮重置 downloads.db**：pipeline 按 (bvid,cid) 去重，重跑会撞去重；开头 `unlink` 保证可复现 → `main_async`
- **probe 固化流程**：`--probe` 只搜+下，打印观测值 → 人工核对 → 写回 cases.yaml 的 `expect`/`bvid`（标准答案来源于实测）→ `_dump_probe`
- **搜索断言抗漂移**：`search_expect.bvids` 成员集（任一命中即可）+ `lyric_hit`（反查确实产出 lyric 来源结果）而非固定 index → `run_case`
- **pytest 隔离**：`@pytest.mark.e2e` + `addopts = "-m 'not e2e'"`（注意引号，否则被空格拆成 path）；conftest 显式 fixture（非 autouse）避免污染单元测试 → `pyproject.toml`
- 歌词行去重生成 gold 工作簿：`seen` 集合保序去重，时间戳清零待人工填 → `gen_gold` 逻辑

## API / 库 速查

- `yaml.safe_load(text)`：解析用例 YAML；PyYAML 需加入 `[dev]` extra → `pyproject.toml`
- `bilimuse.services.search.search_versions(cfg, query)` → `list[SearchHit]`（`.version.bvid/.source`，source=direct/lyric）→ `run_testset.py`
- `bilimuse.services.pipeline.download_song_pipeline(cfg, bvid, page, on_event, no_tag, no_lyric, force_align)` → `{path, meta, lyric, title, artist}`；meta=None 表示反查失败 → `run_testset.py:_download`
- `bilimuse.services.aligner.probe_duration(path, cfg)`：mutagen→ffmpeg 三级取时长（秒）→ `run_testset.py:_check_expect`
- `bilimuse.services.lyric.detect_lyric_language(text)`：ja/zh/ko/ru/en（粤语汉字→zh）→ `_check_expect`
- `fastapi.testclient.TestClient(app).websocket_connect("/ws/download")`：进程内 WS 测试 → `test_web_e2e.py`

## 踩坑

- **同名文件覆盖**：C01(晴天 317s) 与 C28(35s 翻唱) 反查都命中「周杰伦 - 晴天」→ 后者覆盖前者，C01 时长校验炸。→ 每用例独立目录 → `run_testset.py`
- **跨运行去重**：重跑时 bvid 已在库 → pipeline 抛「已下载过」→ 用例 FAIL。→ 缓存优先复用 + 每轮重置 db。
- **缓存 dict 覆盖 Result**：`_record_cache` 曾把文件缓存 dict 写进进程内 Result 缓存 → 复用时报 `'dict' object has no attribute 'path'`。→ 持久缓存与进程内缓存分离 → `_record_cache`
- **PowerShell 重定向双重转码**：`python ... > out.txt` 被 PowerShell 存成 UTF-16 且 GBK 双重转码 → 观测乱码。→ probe 结果由运行器直接写 `report/probe.json`（UTF-8）。
- **lyric_hit 假阴性**：反查歌名已含于 query（如 query「Hello it's me」反查出「Hello」）时，search_versions 按设计跳过冗余 B 站搜索 → lyric_hit=0。→ C08 不设该断言，注释说明。
- **addopts 空格拆分**：`-m not e2e` 被 pytest 拆成 `-m not` + path `e2e` → `-m 'not e2e'` 引号包裹。
- **格式未按用例生效**：cfg.format 是共享单例，用例指定 mp3 没写回 → 全跑成 m4a。→ run_case 开头 `cfg.format = case.get("format", ...)`。
- **复用用例目录为空**：缓存复用只记录路径，不把产物放进本用例目录 → 评审/补听时「无文件」。→ `_copy_to_case`：复用即把音频+侧车 .lrc 拷进 `dl/<case_id>/`，目录永远自足 → `run_testset.py:_copy_to_case`
